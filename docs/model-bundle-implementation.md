# MODEL-001: итерационная реализация

Текущая реализация находится в `main`; первоначальная ветка — `feature/model-001-model-bundle`.
Основание: [согласованное ТЗ](model-bundle-spec.md).

## Этапы 1–3 — реализованы, ожидают оценки

- Лёгкий ModelSpec, абстрактный ModelBundle, ленивый реестр backend.
- Startup вызывает download_model_artifacts для каждой модели и сохраняет
  каталог ModelSpec. Веса, схемы и библиотеки backend не загружаются.
- API принимает задачу с total_rows=null, без чтения данных и артефактов.
- Worker после claim запускает heartbeat, создаёт pipeline, вызывает load,
  проверяет вход, сохраняет total_rows и проверяет пустой выход.
- Общая инфраструктура делит чанк на infer-батчи и проверяет число строк,
  ключи, колонки, неизменность входа и стабильность типов результата.
- Writer получает результаты чанками. Worker проверяет итоговое число строк
  перед FINALIZING и публикацией _SUCCESS.
- Close вызывается в finally, включая частичную ошибку load. Следующая задача
  начинается после close; ошибка close останавливает под без потери исходной
  ошибки и без изменения опубликованного DONE.
- FMCDCardsRunner сохраняет существующие preprocessing и формулы.
  CUDA cache очищается один раз при close вместо каждого infer-батча.
- YAML мигрирован на per-model настройки без aliases старого формата.

После переноса проверки входа в worker model.json исключён из обязательного
контракта. Backend формирует required_columns/output_columns при load.
Имена файлов карт задаются backend и при необходимости
переопределяются через options; генератор manifest больше не нужен.

## Проверки и следующая точка оценки

Проверки 2026-09-16: выполнены 205 тестов, 7 интеграционных тестов PG пропущены
без тестовой БД; остальные проходят. Проверен также набор FastAPI/Pandas/PyArrow
из рабочего Dockerfile в отдельном окружении. Ruff check и format проходят.

Движки разнесены по `app/models/backends/fmcd_cc_dc/` и `fmcd_invest/`.
В каждом — pipeline, локальные зависимости и каталог `utils/` для модельных
классов. Пакет моделистов перенесён структурно в `fmcd_cc_dc/utils/fmcd/`;
реальных исходников в workspace нет. По уточнению пользователя переходный
загрузчик удалён: применяются прямые импорты внутри backend. Препрод будет
развёрнут с нуля, совместимость со старой архитектурой не требуется.
Dockerfile и requirements используют новую структуру. Сборка образов не запускалась:
проверены файлы сборки, но настоящий пакет моделистов ещё необходимо предоставить.

Проверяются startup без импорта backend, отсутствие чтения данных в API,
load/close при успехе, ошибках и отмене, heartbeat во время load, прекращение
работы при ошибке close, последовательные экземпляры без оставшихся ссылок,
остаточный батч из одной строки, чанк меньше батча, ключи и типы выходов.
Формулы проверяются на синтетических logits и заглушке tensor API; отдельно
проверены NaN, маска пропусков и ограничение неизвестных категорий.

Следующая итерация — приёмка на настоящих артефактах: эталонные результаты карт,
серия CPU/GPU-задач и проверка статистики metrics_util_*.
В окружении отсутствуют PyTorch и реальные комплекты моделей. Заглушки не
доказывают численную эквивалентность настоящих весов или освобождение VRAM.
INVEST перенесён 2026-09-17; для приёмки нужны настоящие артефакты, эталон и допуски.
SQL выполняется вне backend; вход INVEST — Parquet с исходными признаками.
Переход со старой архитектуры не входит в работы: препрод разворачивается с нуля.

## Исходное поведение для регрессии

Зафиксировано чтением текущих loader/inference/pandas_to_fmcd; численный эталон
на действующих весах ещё не получен:

- В YAML экземпляр называется `credit_cards`; ключи — `customer_mdm_id`
  и `partition_report_dt`, device — `cuda`, infer-батч — 500, чанк — 5000.
- Численные признаки переводятся в float32; маска строится по NaN,
  затем используется `numpy.nan_to_num(..., nan=0.0)` с текущими defaults для infinity.
- Категориальные пропуски заменяются cardinality; значения приводятся к int64
  и ограничиваются диапазоном `[0, cardinality]`.
- D: sigmoid logits → clip вероятности `[1e-7, 1 - 1e-7]` → logit →
  Platt calibration (`intercept`, `coef`).
- F/M/C: калиброванная D-вероятность умножается на expm1 соответствующего выхода.
  Count: expm1 от `d_count_pred`, без дополнительной калибровки.
- Порядок выходов: ключи, все `d_prob_*`, все `f_pred_*`, все `m_pred_*`,
  все `c_pred_*`, `d_count_pred`. Имена берутся из schema с текущими fallback.
- До миграции модели загружались при startup, а `empty_cache` вызывался в каждом
  infer-батче; в новой реализации cache очищается при close.

## Уточнение 2026-09-15 — утилизация вместо метрик этапов

Метрики этапов удалены. При `calc_utilization=true` worker собирает ресурсы раз в
секунду: CPU/GPU в %, RAM/GPU_RAM в % и МБ. Статистика metrics_util_* считается
в памяти, после close итог выводится в logger. По умолчанию сбор выключен.
[Контракт статистики](task-utilization.md).

Структура backend приведена к runner.py + utils/. Дополнительные функции и классы
находятся в utils. Диаграммы отражают spark-submit из кастомных операторов:
Spark переносит parquet между Hadoop и S3, Airflow получает только статус.
