# Оператор инференса для Airflow 2.6.3

Скопируйте каталог `airflow_operators` рядом с DAG-файлами, чтобы он был доступен
на scheduler и всех workers. Airflow не устанавливается в образ GPU-сервиса.
Дополнительный HTTP provider не нужен: оператор использует стандартную библиотеку Python.

```python
from airflow_operators.model_inference import ModelInferenceOperator

infer = ModelInferenceOperator(
    task_id="infer",
    service_url="http://fmcd-inference:8080",
    s3_input_prefix="s3://input-bucket/credit_cards",
    s3_output_prefix="s3://output-bucket/credit_cards",
    model_name="credit_cards",
    partition_by="shard_id",
    n_shards=8,
    poke_interval=60,
    timeout=24 * 60 * 60,
    request_timeout=30,
)

# Здесь используются ваши существующие задачи перекладки.
prepare_data >> infer >> load_results_to_hadoop
```

Без шардирования опустите оба параметра `partition_by` и `n_shards`.
При шардировании вход и выход получают подпапки `shard_id=0` ... `shard_id=7`.
Каждый входной префикс должен содержать parquet с необходимыми колонками модели.
Все шарды должны быть полностью записаны до запуска; оператор не ищет партиции
в S3. Сервис не требует входного `_SUCCESS` внутри каждого шарда.

`service_url`, префиксы, имя модели и параметры шардирования поддерживают Jinja.
Ожидание работает в `reschedule`: между проверками worker освобождается.
HTTP-запросы выполняются последовательно, сами расчёты идут независимо на свободных подах.
Один проход отправляет/восстанавливает заявки всех шардов и проверяет их статусы.
Каждый HTTP-запрос имеет таймаут и до трёх попыток при сетевых ошибках и временных 5xx.

Ключ идемпотентности определяется DAG, run_id, task_id, map_index, номером попытки
и шардом. После reschedule оператор повторяет `POST /infer` с тем же ключом:
сервис возвращает уже существующую задачу, даже если она завершена. Это также
восстанавливает задачу при потере HTTP-ответа. XCom для хранения состояния не нужен.
История задач на сервисе должна храниться дольше максимального ожидания оператора.
Не меняйте параметры уже работающей попытки.

После DONE всех шардов оператор возвращает в XCom `return_value`:

```json
{
  "task_ids": ["идентификатор-расчёта-0", "идентификатор-расчёта-1"],
  "s3_output_prefix": "s3://output-bucket/credit_cards"
}
```

При FAILED, ABORTED, ABORTING, ошибке API или таймауте сенсора задача Airflow
падает. Оператор отправляет abort известным незавершённым расчётам. Он завершает
проход по всем шардам даже после ошибки, чтобы восстановить их ID для отмены.
Поэтому в этом проходе ещё могут быть приняты заявки, которые затем будут отменены.
При сигнале остановки активного worker также вызывается отмена известных задач.
Во время reschedule процесса оператора нет: ручное изменение состояния в UI
не вызывает on_kill. SIGKILL тоже не позволяет выполнить код отмены.

Отправка abort не означает немедленную остановку: RUNNING становится ABORTING.
FINALIZING возвращает 409 и может завершиться DONE. Недоступность сервиса или потеря
ответа POST может оставить задачу, ID которой не удалось восстановить; ключи запросов
и ошибки записываются в task log. Такие случаи требуют ручной проверки.

Автоматические retries отключены, даже если они заданы в default_args DAG.
Для повторного расчёта:

1. Проверьте завершение/остановку всех старых расчётов. Один FAILED по heartbeat
   не гарантирует остановку старого PUT, особенно при повторе в тот же S3-путь.
2. Запустите вашу задачу очистки только выходного префикса таблицы, не всей очереди S3.
3. Выполните Clear задачи инференса. Новая попытка создаст новые ключи для всех шардов.

Оператор пишет сообщения через штатный `self.log` Airflow, используя только
`info`, `warn`, `error`. Отдельные handlers и logger не создаются.

Модульные тесты используют заглушку Airflow и проверяют контракт с сервисом.
Проверка scheduler/reschedule с настоящей metadata DB выполняется в вашем Airflow.

Поведение reschedule и номера попытки сверено с исходниками
[Airflow 2.6.3 BaseSensorOperator](https://airflow.apache.org/docs/apache-airflow/2.6.3/_modules/airflow/sensors/base.html)
и [TaskInstance](https://airflow.apache.org/docs/apache-airflow/2.6.3/_modules/airflow/models/taskinstance.html).
