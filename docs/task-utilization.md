# Утилизация ресурсов задачи

При `calc_utilization=true` в JSON запроса `POST /infer` worker запускает отдельный sampler перед load модели и останавливает после close.
По умолчанию `calc_utilization=false`: sampler и датчики не запускаются.
В Airflow включение задаётся через `GPUModelInferenceOperator(calc_utilization=True, ...)`.
Раз в секунду измеряются ресурсы; первый замер — через секунду после запуска sampler.
Короткая задача может завершиться без замеров. CPU/RAM относятся к процессу сервиса
со всеми его потоками, GPU/GPU_RAM — ко всему выбранному устройству.
Интервал задаётся монотонными часами; если измерение задержалось, пропущенные
секунды не заполняются повторением старого значения.

| Префикс полей | Единица и смысл |
| --- | --- |
| metrics_util_cpu | % процесса, 100% = одно полностью занятое ядро; возможно больше 100% |
| metrics_util_ram_pct | RSS процесса в % от лимита памяти контейнера, при отсутствии лимита — от RAM узла |
| metrics_util_ram_mb | RSS процесса в МБ, 1 МБ = 1 000 000 bytes |
| metrics_util_gpu | % занятости выбранного GPU |
| metrics_util_gpu_ram_pct | Занятая память выбранного GPU в % от его полной памяти |
| metrics_util_gpu_ram_mb | Занятая память выбранного GPU в МБ |

У каждого префикса есть суффиксы `_min`, `_max`, `_mean`, `_median`, `_samples`.
Например: `metrics_util_gpu_ram_mb_median`. Медиана точная, среднее арифметическое
по успешным замерам. Нулевое измерение учитывается; недоступный датчик пропускается.
До первого измерения статистики равны null, `_samples` — 0. Ошибка датчика не
завершает инференс и логируется один раз для соответствующего показателя задачи.

RAM-лимит берётся из cgroup v2 memory.max или v1 memory.limit_in_bytes и ограничен
физической памятью узла. GPU определяется по UUID устройства PyTorch, чтобы учитывать
CUDA_VISIBLE_DEVICES. Sampler не загружает torch и не инициализирует CUDA ради замеров;
GPU-показатели появляются после инициализации CUDA моделью. На CPU-задаче они null.
Используется [NVML](https://docs.nvidia.com/deploy/nvml-api/api/group__nvmlDeviceQueries.html)
через nvidia-ml-py: занятость GPU и использованная видеопамять — разные измерения.
При неподдерживаемом измерении, в том числе на отдельных MIG-конфигурациях,
соответствующий показатель остаётся недоступным. Показатели GPU не изолируют соседние
процессы на том же устройстве.

Статистика считается только в памяти worker. После close sampler останавливается,
а итоговые min/max/mean/median и число измерений выводятся через общий logger
в сообщении «Задача <task_id>: итоговая утилизация» с JSON полей `metrics_util_*`.
Это выполняется также при ошибке или кооперативной отмене задачи.

В TaskStore хранится только флаг `calc_utilization`, чтобы его получил под-исполнитель.
Флаг входит в параметры идемпотентности: его изменение с прежним ключом даёт HTTP 409.
Статистика не записывается в S3 и не возвращается в GET /tasks/{task_id}/status.
При SIGKILL или рестарте несохранённая в logger статистика теряется.
Для точной медианы sampler хранит две кучи: память пропорциональна числу замеров
и освобождается после выхода worker из задачи.
