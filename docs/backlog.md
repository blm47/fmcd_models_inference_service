# Бэклог

## MODEL-001 — Общий ModelBundle и загрузка на время задачи

Статус: ТЗ уточнено пользователем 2026-09-13; реализация не начата.
Приоритет: до подключения следующих четырёх уникальных pipeline.
Полное ТЗ и порядок миграции: [ModelBundle](model-bundle-spec.md).
ТЗ имеет приоритет над первоначальным предложением startup-загрузки.
Разбор прототипа: [FMCD_INVEST](fmcd-invest-review.md).

Проблема: текущие loader, ModelBundle, валидация входов и worker рассчитаны на
один формат FMCD. FMCD_INVEST требует CatBoost, собственного preprocessing,
нейросетевого stacking и других выходных колонок.

Объём POC:
- Общий ModelBundle: load / predict_batch / обязательный идемпотентный close.
- На старте только YAML, без чтения manifest, схем и обязательных колонок.
- Контракт входов выбранной модели читается при новом POST /infer без загрузки весов.
- Загрузка только после захвата задачи, выгрузка после каждой задачи, без кэша.
- Реестр backend → класс; уникальный backend на новый pipeline, переиспользование
  для общей логики (например, ДК/КК); один корневой каталог артефактов на модель.
- Выполнение в текущем процессе с close, без накопления объектов между задачами;
  отдельный процесс и строгий возврат RSS/VRAM к исходному уровню не требуются.
- Адаптер текущего FMCD без изменения результатов и отдельный FMCDInvestModel.
- YAML на модель: name, backend, artifacts_dir, id_cols, device,
  infer_batch_size, parquet_read_chunk_size; специфичные параметры через options.
  infer_batch_size — батч для заданного device, CPU или GPU.
- Worker и API используют интерфейс; S3, очередь, прогресс, отмена и публикация
  результата остаются общей инфраструктурой.
- SQL первого этапа: выборка, типы, подтверждённый zero-fill; обучение preprocessing
  не выполняется при scoring. Полный preprocessing в SQL — последующая оптимизация.

Критерии готовности:
- Startup/API не загружают модели; load/close проверены при успехе, ошибках и отмене.
- Следующая задача не начинается до выгрузки предыдущей; память проверена серией запусков.
- Существующая модель даёт прежние результаты; оба backend подключаются конфигурацией.
- FMCD_INVEST совпадает с эталоном по промежуточным стадиям и конечным 14 колонкам
  в согласованной погрешности; обработка чанками сохраняет ключи и число строк.
- Проверены null/NaN, неизвестные категории, порядок признаков, границы и округление.
- Сохраняются работа без шардов и с ними, reschedule, отмена, ошибки, ETA и _SUCCESS.
- Зафиксированы latency этапов и память для CPU и GPU, без загрузки всего dataset в RAM.

Зависимости: полный SQL/ноутбук, комплект артефактов, подтверждённый контракт ключей,
эталон и допуски. Не включать в POC Triton, hot reload или универсальный DAG pipeline.
